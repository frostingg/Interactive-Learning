# 题内问答

## 前提与范围

此技能是互动题卡的工作流，不是宿主消息渲染器。它无法拦截、编辑或替换 ChatGPT 的所有原生消息。只有宿主已连接本插件 MCP 服务并提供 create_board / get_board / ask_card 时才能使用交互界面。
如果这些工具不可用，明确说明未连接，不把静态文本称为互动卡片，也不要虚构工具或安装成功。

## 首次回答

1. 将用户的问题逐一整理，保留原问题的顺序。不要遗漏问题；一次最多 30 题，超过上限分组创建。
2. 独立计算、核对并完成每道题的初次答案。题目与答案写入 create_board 的 cards（question、answer）；title 使用简短自然标题。
3. 调用 create_board，让插件显示同一组题卡。请保留返回的 board.id 和各 card.id 以供后续上下文使用。
4. 主聊天仅简短提示“可在任意题目内继续追问”。不用在聊天里重复全部答案。

用户明确说“此会话以后每次都这样回答”时，将本工作流持续用于当前会话的学习问答；其他会话的激活由宿主设置决定，不能承诺全局自动生效。

## 题内追问

默认追问由卡片直接调用 app 可见的 ask_card，服务端在该题下生成和保存解答。不要通过 ui/message、sendFollowUpMessage 或新的聊天转发按钮实现题内追问。
不要把本题之外的其他问题传给局部模型。局部模型只收到当前原题、原答案及本题的历史。

用户在主聊天主动问“第三题为什么这样”时，可以正常解释；说明这次请求来自主聊天。不要声称原题区域已更新，也不要重新创建全部题卡。
如需重新打开已有答题板，可先调用 get_board 读取板块，依据宿主提供的打开方式展示；get_board 本身不会挂载新的组件。

## 真实性

- 预设演示答复不属于 AI 生成，应明确标注。
- 未配置模型服务、连接不可用或保存失败时保留用户输入，报告可恢复错误。
- 原答案可能有误，局部解答应核对并纠正。
- 不保证普通 Chat 模式、每个账户或所有客户端都支持插件；根据已验证的宿主能力说明。
